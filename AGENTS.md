# AGENTS.md — Standing Instructions for AI Coding Agents

This file defines the project architecture, permissions, conventions, and verification standards for AI coding assistants working in this repository (following the **ETF5560 Module 3** standard).

---

## 1. Directory Map & Permissions

| Directory / File | Role | Agent Permission |
| :--- | :--- | :--- |
| `data/raw/` | Immutable source inputs (`reviews.csv`, `additions.csv`, `cap_overrides.csv`, `known_members.csv`). | **READ-ONLY.** Never overwrite, edit, or delete files in `data/raw/` without explicit user approval. |
| `data/interim/` | Intermediate pipeline outputs (`review_schedule.csv`, `reference_caps.csv`, universe lists). | **READ / WRITE** (generated by `code/01_schedule.py` – `code/04_reference_caps.py`; git-ignored). |
| `data/derived/` | Analysis-ready regression panels (`review_01.csv` .. `review_06.csv`, `matched_controls.csv`). | **GENERATED BY CODE ONLY.** Never hand-edit CSVs in `data/derived/`; modify `code/05_match_controls.py` or `code/06_build_panels.py` and re-run. |
| `code/` | Numbered pipeline scripts (`01_schedule.py` .. `07_validate.py`, `08_run_asx300_analysis.R`, `common.py`). | **READ / WRITE.** Keep scripts numbered in execution order. |
| `output/tables/` | Regression tables and statistical test CSVs generated by `code/08_run_asx300_analysis.R`. | **GENERATED BY CODE ONLY.** |
| `output/figures/` | Publication plots (`report_figure_1..4.png`) generated by `code/08_run_asx300_analysis.R`. | **GENERATED BY CODE ONLY.** |
| `output/logs/` | Validation logs (`qa_report.md`, `VALIDATION.txt`, `R_session_info.txt`, candidate/status logs). | **GENERATED BY CODE ONLY.** |
| `docs/` | Project documentation, `data-manifest.md`, `decision-log.md`, and `MANIFEST_SHA256.csv`. | **READ / WRITE.** Update `docs/decision-log.md` whenever empirical rules change. |
| `report/` | Final human-facing deliverables (`ETF5560_Group_E.pdf`, `ETF5560_Report_V3.docx`, `.pptx`). | **READ-ONLY** unless the user specifically asks to update the manuscript or slides. |

## 2. Exact Commands to Run, Test & Verify

- **Run R Econometric Analysis (Tables & Figures):**
  ```bash
  Rscript code/08_run_asx300_analysis.R data/derived output/tables
  ```
- **Run Python QA & Panel Integrity Validation:**
  ```bash
  python code/07_validate.py
  ```
- **Rebuild Derived Panels from Cached Market Data (Steps 4–7):**
  ```bash
  python code/04_reference_caps.py
  python code/05_match_controls.py
  python code/06_build_panels.py
  python code/07_validate.py
  ```
- **Run Full Pipeline End-to-End (Steps 1–7):**
  ```bash
  python run_all.py
  ```

## 3. Project Conventions

1. **Path Resolution:**
   - Never use hardcoded absolute paths (e.g., `C:\Users\...`).
   - In Python, import `ROOT`, `CONFIG`, `INTERIM`, `OUTPUT`, `LOGS` from `code/common.py`.
   - In R, resolve paths relative to the repository root or via command-line arguments (`INPUT_DIR`, `OUTPUT_DIR`).
2. **Naming & Numbering:**
   - Scripts in `code/` are prefixed with two-digit execution numbers (`01_` through `08_`).
   - Review IDs use zero-padded two-digit strings (`R01` through `R06`), corresponding to panel files `review_01.csv` through `review_06.csv`.
3. **Econometric & Data-Cleaning Rules:**
   - **Zero-Volume Days:** Zero-volume days (`volume <= 0`) must never be filled with zeros or arbitrary constants (such as `1e-6`) in log or ratio dependent variables (`amihud`, `log_dollar_volume`, `turnover_rate`, `log_turnover_rate`). They are coded as `NA` / `NaN`, while genuine zero returns (`daily_return == 0` with `volume > 0`) remain valid (`amihud = 0`).
   - **Window Averaging Before Logs:** In `code/08_run_asx300_analysis.R`, daily Amihud is averaged within each event stage first, and the natural logarithm is taken after window averaging.
   - **Control Matching Without Replacement:** Each matched addition is paired with 2 unique controls within the same review (`N_CONTROLS = 2`) without replacement, subject to the $\text{A}\$100,000$ baseline (`[-30, -11]`) median daily dollar-volume gate (`MIN_BASELINE_DOLLAR_VOL`).

## 4. Definition of Done

A task modifying code or data is only complete when:
1. `python code/07_validate.py` exits with code `0` and updates `output/logs/qa_report.md`.
2. `Rscript code/08_run_asx300_analysis.R data/derived output/tables` exits with code `0`, confirming all 77 matched groups, 231 stock-review units, and 187 ticker clusters pass every internal assertion.
3. No personal machine paths (`C:\Users\...`) or API keys appear in any tracked file.
4. Any methodological change is logged in `docs/decision-log.md`.

---

## 5. Guardrails (Never Do Without Asking)

- **NEVER** commit, print, or stage `.env` or any file containing `EODHD_API_KEY`.
- **NEVER** modify files in `data/raw/` (`additions.csv`, `reviews.csv`, `cap_overrides.csv`).
- **NEVER** delete or overwrite `data/cache/` without confirming with the user, as re-fetching EODHD and Yahoo Finance histories takes ~20 minutes and consumes API quota.
- **NEVER** run `git push --force` or destructive Git commands.
